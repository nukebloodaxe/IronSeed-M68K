# Iron Seed STE — assembler conventions (ABI)

Every routine in `kernel/` and in the screen modules follows these rules. A routine that breaks one says so in its header comment.

## Machine state
- The program enters **supervisor mode once** at start-up (`Super(0)`) on its own 8 KB stack, and stays there until exit. Hardware registers can be touched anywhere. GEMDOS/BIOS/XBIOS traps are still allowed from main code (TOS accepts them in supervisor mode), **never from interrupt handlers**.
- Main code runs at **IPL 3** (`sr = $2300`). Code that must not be interrupted uses `move.w sr,-(sp) / move.w #$2700,sr … move.w (sp)+,sr`, for as few cycles as possible (it delays the raster splits).
- On exit the kernel restores: screen base, resolution, palette, all vectors it changed ($70, $114, $118, $120, IKBD vectors), MFP IERA/IMRA/TBCR/TBDR, DMA sound off, user mode. The mouse position is handed over: the kernel's cursor starts where GEM's pointer is and GEM's pointer is moved to the kernel's at exit (kbd_init / kbd_tos_sync, Phase 6c) - never reset kbd_mx/kbd_my to a fixed place outside test runs.

## Registers
| Register | Use |
|---|---|
| d0–d2, a0–a2 | **scratch** — any call may change them (same set as TOS [expertise §2.2]) |
| d3–d7, a3–a5 | **preserved** — a routine that uses them saves and restores them |
| a6 | **GS = global state base** — set once at start-up, never changed, never saved; all game globals are `OFFSET(a6)` |
| a7 | stack; keep it even; no data below `sp` (interrupts use the same stack) |

## Calls
- `bsr`/`jsr` and `rts`. Arguments in registers, documented in the routine header in this form:
  `; in: d0.w = colour, a0 = string  out: d0.l = width  trashes: d1-d2/a0-a1`
- Integer arguments in d0, d1, d2 (then d3+ only when unavoidable, documented); pointers in a0, a1 (then a2).
- **GEMDOS/BIOS/XBIOS traps trash d0-d2/a0-a2** like any call (d0 = the result). Hatari's and Steem's emulated drives keep them, so the tests never see a register kept across a trap - real TOS on a real disk may not: keep values in d3-d7/a3-a5 or memory (Phase 6g: IS.PRG's Pexec tail, sys_init's return address).
- `tools/reglint.sh` checks all of this across calls and traps (in run_tests.sh; zero reports expected). Header comments `out: d0.w = ...` (or `out: -`) tell it a routine's results; without one it takes the registers most call sites use.
- Results: integer in **d0**, pointer in **a0**. Flags: when a routine can fail it returns with **carry set** on failure and `d0` = negative TOS error code, carry clear on success.
- Sizes: `.w` for the original's `integer`/`word` (16-bit), `.l` for `longint`, `.b` for `byte`/`boolean`/`char`. Booleans are bytes, 0 = false, $FF or 1 = true (test with `tst.b`).

## Interrupt handlers
- Save every register they touch; end with `rte`. No TOS calls, no VDI/Line-A [expertise §3.3].
- Timer B (raster split) has priority: no other handler may hold IPL 6 for more than a few dozen cycles without first lowering to `#$2500` (see the Timer C/ACIA wrappers in `spikes/jitter.s`).
- MFP is in software-EOI mode: clear the in-service bit at the end (`bclr #n,ISRA/ISRB`).
- The VBL handler does: band-0 palette, Timer B restart, screen swap, the module's `vid_vbl_hook` (if set), cursor, mixer refill; then chains to the TOS VBL.
- `vid_vbl_hook` (long, 0 = none): a screen module's per-frame routine, called while the beam is still in the top border (~45 lines before line 0 at 60 Hz). It may trash d0-d7/a0-a3 only, makes no TOS calls, and must be short (the mixer runs after it). Clear it before the module leaves. First user: the logo scene in `game/intro.s` (`nb_vbl`).

## Memory and data
- Everything big-endian, words and longs at **even addresses** (an odd word access = address error). Records follow the layouts generated by `tools/rec2equ.py` into `build/layout.i`: fields in the original order, words/longs padded to even offsets, record sizes rounded up to even.
- Strings keep the Pascal shortstring form of the original (length byte + characters) so game logic ports line by line.
- Buffers for DMA sound and the screen must be in ST RAM (all RAM on an STE). Screens on 256-byte boundaries (STE allows word boundaries, but keep 256 for STF-style tools and Hatari dumps).
- Allocation: `mem_alloc` (kernel) wraps a single large `Malloc` taken at start-up — TOS 1.x allows only ~20 `Malloc` fragments per process [expertise §16].

## Fixed point
- Angles: 0–1023 for a full circle; sine/cosine tables of words ×16384 (2.14), multiply with `muls` then `asr` 14 (or `add.l` + `swap` for ×65536 tables) [expertise §11].
- Positions/velocities: 16.16 in longs unless a module says otherwise.

## Reals (Phase 4b: kernel/fp.s, MAIN only)
- Pascal `real` is an IEEE double in big-endian order in the GS layout. Compute with the software FPU's stack (`fp_ldd/fp_ldi/fp_ldw/fp_ldx` push, `fp_add/sub/mul/div/sqrt/sin/cos/atan`, `fp_std` pop to a double, `fp_rnd/fp_trunc/fp_cmp/fp_str` pop to integers/flags/strings). All fp_ routines trash d0-d2/a0-a2 only; the stack lives in fp.s, so balance pushes and pops within a routine.
- Phase 6i: `fp_sin`/`fp_cos` compute both (kernel `fpi_fsc`, bit for bit `tools/sincos_model.py`) and keep the pair for the last argument: call them in any order; results are the x87's 64-bit values (97.8 % bit-exact, never different as doubles in the tests).
- Set the rounding unit before each expression: `FSSE` (FPC's SSE: plain double expressions, sqrt) or `FX87` (FPC's x87: a literal that is not double-exact, sin/cos/arctan). Leave `FSSE` set on return. Literals come from build/gconst.i (`gx_0_049` …, tools/mkgconst.py) as 10-byte extendeds (`FLDX`); add new ones to its LITS list.
- Integer sub-expressions are evaluated by FPC in native width (64-bit): sum words in longs before `fp_ldi`.

## Names
- Kernel routines: `vid_`, `snd_`, `kbd_`, `tim_`, `fil_`, `mem_`, `gfx_`, `txt_`, `pic_` prefixes. Screen modules: prefix from the original unit (`cargo_`, `comm_`, `explore_`, …) plus the original Pascal procedure name, so oracle mismatches map back to the Pascal source.
- Local labels `.name`; equates UPPER_CASE; generated layout equates `REC_FIELD` (e.g. `SHIP_FUEL`) and `GS_name` for global offsets.
- One routine per Pascal procedure where practical; keep the Pascal source line references in comments (`; journey.pas:559 makesphere1`).

## MAIN.PRG's screen (Phase 4)
- The game draws into the chunky shadow (`ms_*` in game/mscr.s, original palette indices, the original's coordinates) and marks what it changed; `mouseshow`, `delay` and `ms_flush` convert the dirty spans to the planar screen. `mousehide`, `mouseshow` and `delay` are ordinary calls: they trash d0-d2/a0-a2.
- Phase 4g: `ms_vscroll` moves rows on the planar screen exactly as the caller then moves them in the shadow (which it does not mark: a copy instead of a conversion; rows whose source is in another band get marked dirty instead), `ms_psetp` sets one pixel in both at once (cursor hidden). Both keep the shadow and the planar screen in step without the flush - use them only where the caller's shadow change is exactly what they mirror.
- Phase 6h, the cursor: MAIN's `mousehide` is **soft** (kernel `kbd_cursor_soft`): the game only draws into the shadow, so the cursor stays drawn and keeps following the mouse; `mouseshow` ends it (`kbd_cursor_shownow`: drawn at once, not at the next VBL). A soft hide that lasts KBD_SOFTV (50) frames without a mouseshow is ended by the VBL (the cursor goes, as in the original's long hidden stretches). Code that writes the **planar** screen itself uses `mousehidep` (= `kbd_cursor_hide`, a real hide): the sprinkles, landsprinkle, the ending. `ms_flush` keeps the cursor up: it sets `kbd_busy` (line+1) before converting a line - the VBL never draws the cursor over that line - and lines under the drawn cursor are converted beside it first, its 32 pixels last with it off for just that moment.
- Phase 6i, the bridge's designs: MAIN (planets), MAINS1-3 (a star of mode 1-3) differ only in band 1; `u2_design` (utils2.s) switches by the orbit and records it in `ms_design` (mscr.s), which ms_snap/ms_unsnap keep with the screen. A new screen that rebuilds the bridge without readystar/readyplanet should call u2_design after it.
- Routines that take d3/d4 as arguments (x2/y2/colour, like the kernel's gfx_bar) keep the caller's d3/d4 only if they are the callee; a helper that loads d3/d4 to call them must save them (ABI: d3-d7 preserved).

## Determinism and tests (Phase 3)
- Random numbers that affect game state come from `mt_random` (FPC's generator, kernel `mt.s`), called in the same order as the Pascal code, so state dumps match the Linux oracle. Where the Pascal argument is an arithmetic expression (random(a+b), random(n-1)), the x86-64 oracle calls FPC's random(int64): use `mt_random64` there. `rnd` (LCG) is only for visual noise that the original made with its own random calls where exact sequences do not matter (the intro).
- `scr_test` = 1 when a script file was found: fixed seed 1994, `orc_dump` writes `C:\Dnnnn.BIN` at every point where the original calls loadscreen. Programs may skip their command-line check in test runs.
- A screen module that switches band designs must redraw everything visible afterwards (the planar pixels hold slots, not colours).
- Phase 6i: after `mt_seedc` the draws may read a kept state in place (`mt_cur`); code that reads or writes `mt_state` itself must call `mt_own` first (keeps every register).
- Phase 4c: `mt_random64l` (d0.l) is random(int64) of a long argument; FPC's `randseed` variable is `mt_getseed`/`mt_setseed` (lazy: the generator re-seeds at the next draw when the variable changed), so ports of `randseed := x` / PushRand/PopRand use those, never `mt_seed`.

## Music stream (Phase 6b)
- `mod_load` streams `MUSIC\NAME.RAW` when it exists. Main code refills the stream: `tim_delay`, `kbd_keypressed`, `vid_flip` and MAIN's `ms_flush` call `snd_poll` (one GEMDOS Fread when the ring has room; changes no registers, flags aside). A new loop that runs longer than ~40 s (the ring holds 84 s at 6258 Hz, 42 s at 12517) without any of those must call `snd_poll` itself. Never from interrupts.
- The VBL owns `st_rd`, main code `st_wr`; `mod_stop` closes the stream file, `pausemod` (clearing mod_on) only pauses it.
